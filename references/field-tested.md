# H3 实测定论（2026-09-28 ~ 09-30）

> 来源：C 的实测系列 E1~E25（原档《定论.md》）。
> 原则：**实测 > 文献 > 推断**；与官方口径冲突时以本文件实测为准（仅限已实测范围）。
> 范围：只收「模型行为 + 写作对策」。调用参数语义、硬件与成本数字不在本 skill 范围。

## 1. 分辨率：短边 768 是唯一安全点 ⭐⭐⭐

- 规则：**短边锁死 768，长边与画幅方向随意**（竖 768×1024、横 1344×768 都在基准上）
- 两侧塌的是**不同的层**：

| 偏离方向 | 塌的层 | 实测表现 |
|---|---|---|
| 低于 768 | **画面层**（空间/高频） | 空间拓扑被重释（草帽"挂背后"→"戴头上"）、五官糊、局部缺失 |
| 高于 768 | **语义层**（时序/动作逻辑） | 多阶段时序被合并、动作状态被简化（"双手展开后提裙"→"单手"） |

- 阈值是**线性的**（容忍度），不是开关——不存在安全边界
- **720p 是"抽签"档**：同 prompt 跨 seed 锐度极差巨大 ⇒ **跳过该档**
- 768p 健康性获独立压测支撑（9 发 = 3 分辨率 × 3 seed）
- ⚠️ "跨分辨率画的不是同一镜头"是无锚时代现象；带 FL2VA 双锚后构图已被锚定，勿迁移到带锚场景
- 细节天花板由 latent 压缩决定：**加 steps 补不了细节**（官方 flow matching 文档同口径）

## 2. steps 与 duration 正交：改动作别加步数 ⭐⭐⭐

| 旋钮 | 控制 |
|---|---|
| **steps** | 仅呈现质感（锐度）。改不了"做什么"，也改不了"多清楚" |
| **duration** | 节奏/摊开程度（同一动作量摊在多久里） |

- "步数=动作总量"只在**语义连续动作**（转几圈）上成立——那是 prompt 语义被步数改变采样完成度的特例；
  周期动作探针（挥手）实证 steps 20→50 频率/幅度/总量**全不变**
- **步数维持默认 20**（base 档；turbo_lora=1 时配 8，1.0 蒸馏配比即 8 步）：武戏 20 步不崩（20/30/40/50 无可辨差异）；要细节 onset 下移一档要 ×2.6 时间，不值

| 想要 | 怎么调 |
|---|---|
| 动作更快/紧凑 | 缩 duration 或写节奏词（"快速""均匀节奏"） |
| 更多/更丰富动作 | **改 prompt**（契约版分段、事件逐条列）——加 steps 无效 |
| 更慢更稳（文戏） | 保持 steps，**拉长 duration** |
| 更细腻画质 | **改景别**（见 §3），加 steps 低效 |

- ⚠️ 手部是例外两面：steps 对手是**放大器**（50 步比 20 步更残缺——手是先验弱区，多步把错误结构渲染出来）

## 3. 脸框-细节阶梯（要"多清楚" → 查表反推机位×画幅）⭐⭐

E12+E13+E14 定稿：

| 想要 | 需要脸框 | 达成组合（实测） |
|---|---|---|
| 睫毛/皮肤纹理（细节级） | **≥315 px** | **MS 半身@768p 即可**；任何画幅的全身都到不了 |
| 眉毛毛流/唇纹（二级） | ~175 px | WS 全身@1440p（升档在 1440p 封顶，性价比差） |
| 五官分明/耳环镂空 | ~116~137 px | WS 全身@1080p |
| 五官可辨（底线） | **~96 px** | WS 全身@768p |
| 人形轮廓 | 33~96 px | 任意（走远/大场景） |

关键结论：

- **脸框大小主导细节，画幅只是达成脸框的手段**（同 80~96px 下 768p 与 1080p 同清晰档）
- **性价比拐点 = MS 半身@768p**（相对特写只少 ~21% 脸像素，锚点全在）；**不要用全身保脸**
- **参考上限 ≈ 输出脸 400 px**：>400px 不再获得新细节，真上限在源图（参考端 ~124px 脸已过剩）
- **时间预算是独立杠杆**（E11-1b）：加 duration 能把已有像素"吃满"（细节整体抬一档，像素反而略降）。
  顺序：**先给足时间（吃满像素），再改景别（抬天花板）**
- **zoom-out 白拿一个子档**：先特写后拉远，小脸带着"刚看过清晰脸"的时间上下文，比 zoom-in 冷启动高约一档；
  拉远 prompt 要加"全程保持人物面部完整在画面内"
- **拉远占比句靠不住**（写"占画高 1/4"实际 6 成）：想小脸靠场景设计（走远/大环境）
- **竖屏全身脸框 ≈ 横屏全身**（~96px 同档）：多出的垂直像素分给环境。竖屏预演的正当用途 =
  动作/姿态/服装预演与一致性素材，**清晰度不过继**
- zoom 单条扫描法（工具）：一条 10s"镜头匀速推近"连续扫过脸框全程，0.5s 步进抽帧判读，
  一条扫描条替代 4~6 条离散视频；跨尺度比细节能量必须先归一到同尺寸

## 4. 事件丢失三类规律（复合动作）

| 丢失类型 | 实测表现 |
|---|---|
| **低信息量动作被整段吃掉** | "推门"0.4s 全空 → 0.6s 人已在门边，无过程帧 |
| **大幅动作被压扁** | "蹲下捧起"只剩 0.4s 弯腰，无屈膝下蹲 |
| **道具遮挡 ⇒ 不可判定** | 举胸前的道具挡掉双手与前臂，无法计数 |

规律：**模型优先保"结果状态"（人在场内、熊在手里），牺牲"过程动作"（开门、蹲下的过程）**。
要让动作可判定：给它**独立可见通道**——不被遮挡 + 足够时长 + prompt 结构位（见 §5）。

## 5. 契约版 prompt（事件不丢 + 计数可执行的完整配方）⭐⭐

旧"六段无秒数四板块" → **契约八段 shot**：时间戳分段 + 每段景别/运镜/拍数/音效 + 素材编号 +
首尾帧衔接说明 + 独立「不想要」段。实测（E11-2/E11-3）：

- 被"六段式"吃掉的事件（推门/蹲下）在契约版**全部回归**，拍数结构（两拍/三拍）被显式执行
- **时间戳 = 顺序可靠、刻度不可靠**：中段漂移 +0.9~1.4s，靠尾帧钉回收敛
  ⇒ 契约时间戳**不能当剪辑对齐依据**，分段拼接按素材实际内容找切点
- **计数配方 = 次数个子窗 + 窗间静止态**：一个动作次数 = 一个子窗，窗与窗之间必须写
  "回到某静止态"（给回落一个明确的"家"）；单写"明确的 N 次往复"压不住（会连续摆无回落）
- **动作计数不是模型硬限制，是 prompt 结构问题**
- 首尾帧素材不占 `@图片N` 编号——编号只指参考图清单

## 6. C 路线：链式首尾帧法正式可用（E21）

机制：**段 N 的实际尾帧 → 段 N+1 的首帧**。

- 切点画面字面连续 + 语义状态延续（位置/持物/朝向全继承，无瞬移无重置）
- **分段后事件执行率不降**（4s 短段 + 子窗配方照样计数）；总代价与整条同量级；景别/时长分段自由
- ⚠️ **段间矛盾细节会被链帧继承**（C1 门没关 → 全程门开着）⇒ **切点前检查尾帧状态**
- ⚠️ "固定机位"契约拦不住段内自推近（走近动作 ⇒ 景别自然升级，是链式法默认行为）
- ⇔ **复杂事件链默认走分段**；一镜到底仅用于确实需要连续机位的场景

## 7. 景别不对称律：推近易、拉远难（E24）

| 冲突方向 | 谁赢 |
|---|---|
| 近锚 + prompt 远景词（连负向"不要推近"） | **首帧完胜**（全程钉住） |
| 远锚 + prompt 中近景词 + 动作 | **prompt/动作赢**（1s 内推近，首帧只活 0.6s） |

- 模型自带"向中近景聚拢"先验，首帧锚顺着先验才锁得住
- 实操：**远→近直接写 prompt（自推近免费拿）；近→远 prompt 无效，必须换远构图首帧或剪辑**
- 附：挥手计数在景别冲突下照常执行 ⇒ 语义层与构图层解耦

## 8. 参考图三定律（E11-1c / E12 / E12-b，FL2VA+T2VA 双模式互证）

1. **对细节无用**：超分/纯插值双路线全测完——放大参考图**零增益**（输出端脸像素多 44% 锚点反而更差）
2. **对构图/相位是扰动源**：参考图像素尺寸 ≈ **一次隐藏的 latent 初始化条件**，改它 = 换轨迹。
   冲突越大越显眼（构图三级：景别/站位 → 始终存在的微表情/动作相位 → 细节层不出现）
3. **提示词约束强度可压制构图扰动**（分层分格填空）；但**参考图只承担"外貌"，别指望它定构图**——锁构图上首尾帧，稳构图把文字约束写死到"层"的语义

推论：**参考图给到 ~1776px 就够**，往上加只会撞歪轨迹且 +25% 耗时。放大参考图路线彻底关闭。

## 9. 已封死的方案（不要再试）

| 方案 | 封死理由 |
|---|---|
| **降分辨率草稿** | 初始噪声形状由分辨率决定 ⇒ 降分辨率数学上等于换 seed；且落画面塌缩区 |
| **近似加速混用**（同一条链路一半近似一半精确） | 近似计算破坏步数一致性（8↔30 步对不上）；要用就草稿终稿都用，绝不混用 |
| **低清草稿→高清 refine 两段式** | 草稿档画面层塌 + refine 档语义层塌，两头踩雷；插值补的细节风格不一致 |
| **超分到 >768p** | 高侧塌语义 |
| **放大参考图** | 零增益 + 扰动构图/相位 + 25% 耗时（§8） |

## 10. 其他定论

- **turbo LoRA = 生产默认快档**（E30/E32/E33/E36）：`turbo_lora=1` + `steps≈8`，T2VA/FL2VA/Ref2VA 三形态全实证 2.05~2.72×，四轴失效模式（元素过拟合/镜头退化/伪影/一致性）与 base20 持平。已知代价：①运动模糊略强（8 步自然结果）；②多动倾向（E30 +38%），**节奏型动作把子窗间回落段写足**即可；③edit 档每步 ~4× 于 T2VA，排期按此放大。turbo 生效核验：执行快照 LoRA 节点 strength=1.0 + 耗时比 + 产物形态三证

- **手部配方（E18/E19c）**：手部镜头**标配负向词**（`手指残缺，手指粘连，多余手指，缺少手指`
  ——免费、去残缺主功，50 步 3 级残缺 → 1 级；该配方的实测基线是 base20，turbo8 下未单独验证，勿把手部达标归因为负向词）；手部**特写**另加手参考（成功帧截手区 320² →
  Lanczos 768² 当第二参考，是结构/形状锚）；步数维持默认（base 档 20 / turbo 档 8）
- **edit 档（参考视频/音频）negative_prompt 不生效**（E33 get_tool_info 核实 + 实测），契约里别排负向段；首尾帧语义同样不生效
- **道具尺寸锚 = 保险词**（E23）：可用、免费、无副作用，但治不了巨化；道具尺寸由
  **场景语义 + 参考图**决定；真巨化走先缩后放。无首帧锚时场景自由发挥，**要锁场景必须给首帧**
- **服务端确定性已实证**（E12 重复性对照）：同 seed + 同 prompt + 同尺寸 ⇒ 同果
  （同相位帧 MAE≈2.1~2.5 = H.264 编码噪声级，口型/手势/表情相位全对齐）——**仅限同一实例配置内**。
  ⚠️ 跨实例/重启后确定性破缺（E30：同参数 MAE 28.2 vs 同实例基线 2.2）⇒ 跨实例 A/B **禁用同 seed 暗对照**，须显式重跑基线（E20c 校准法：每次网关升级跑一条回归条）
- **度量纪律（E35）**：同 seed 跨配置**不锁构图**（seed 只锁噪声，任何权重/注意力扰动都会让编排分叉）⇒ 帧间 MAE 均值口径在跨臂对比中必然被编排分叉污染；固定机位稳定性用**相位相关全局平移 + 空间中位数**。该口径对高频抖动与背景纹理漂移**不敏感**（零平移 ≠ 不抖）
- **attention 精度（E10/E22）**：块稀疏（sparse）与致密（dense）是**两条不同的采样轨迹**
  （无锚时代首帧差 16.25 dB，双锚时代 MEAN 5.9 分叉只在动作区）。
  dense 画质相当（−8.2% 容差内）但更慢 ⇒ dense 可当"同 seed 温和重roll"手段。
  ⚠️ 命名直觉帮倒忙：`dense` 不等于"更精确原版"
- **模型层通病（E36，换档解决不了）**：①**反先验动作不服从**——与物理/常识冲突的动作词（"倒退行走"类）可能被语义层直接吞掉、回退为常规编排，base 与 turbo 同样发生（接受，或剪辑/分段实现）；②**数量词不守恒**——"一只猫"可能增殖为两只
- **首尾帧锚定力**：真 FL2VA 首帧 MAE≈3.7/4.0（复现级）；无帧约束时模型按 prompt 文字自绘场景。
  ⚠️ 历史更正（E20a）：E11-2/3 的"尾帧回归"判的是内容层不是图层——契约版事件结论因此更干净
- **中文字幕最可靠兑现路径 = 尾帧图锚定**：先出字幕尾帧图，首帧 + 尾帧双锚同传，
  别让模型自己渲染字幕
- **度量纪律**（实验者用，三次同型教训）：判定"动没动"禁用点位 PSNR（周期动作转满一圈虚高 →
  误读静止）与纯亮度差（慢动作误读静止）；用**空间集中度 + 左右偏向翻转**；跨片对比只能用
  "同坐标、同裁剪、同倍率"并排图；**相位不对齐 ⇒ 数值判据作废**（24fps 下 0.5s 横跨一个完整表情，
  必须逐帧挑动作相位对齐帧）；超现实场景（星空闪烁/漂浮道具）差分法自动量包围盒失效，只能人工标定

## 11. 版本适用性与回归习惯

- E10 同参数回归证明**采样轨迹未变**（首帧 PSNR 27.55 dB、21 个采样点逐点重合）；
  E20c 建立习惯：**每次升级后跑一条同参数回归条**（实测 MEAN 1.9 ≤ 确定性基线 2.2 ⇒ 无回归）
- **换机器 / 换版本 / 怀疑"结论怎么不灵了"：先做同参数回归**（拿旧产物比首帧 + 逐秒 MAE），
  再决定要不要重标定——比读文档猜、比读源码查都快且准
