# 官方垂类配方（`skills/` 下 8 个 style skill 的 H3 层提炼）

**来源**：`MiniMax-AI/MiniMax-H3` 仓库 `skills/` 目录，2026-08-05 起陆续加入的 8 个垂类 skill，
口径 pin 到 commit `a107547`（每类含 `SKILL.md` + `SKILL.cn.md` + `meta.yaml`，两类带 `references/` 模板）。
原文不落盘；这 8 个包本身可安装，遇整包需求建议让用户装成独立 skill（判据、话术与命令见 **§十一**）。

**只收什么**：这 8 个包是**端到端流水线**（brief → 素材生成 → 分镜 → 单镜 → 合成 → BGM → 审核门）。
本文件只抽「决定 H3 提示词怎么写」的部分；平台流程、画布交付、审批卡片、多轮改写不在内。

## 一、结构 / 风格分层（8 个垂类的共同底座）

写之前先把它拆成两层，混着写是最常见的返工原因：

| 层 | 内容 | 处理方式 |
|---|---|---|
| **锁死层** | 事件时间线、镜头顺序、屏上文本、角色身份、动作结果 | 逐条写死，不随风格变 |
| **填充层** | 画风、色调、材质、光向、字体质感、UI 表面 | 按用户选的风格**整段替换** |

冲突时按此优先级裁决（高者胜）：

| 序 | 层 | 用途 |
|---|---|---|
| 1 | 用户明确选定的风格 | 压过源提示词自带风格 |
| 2 | 已确认的确认图 / UI 参考 | 锁布局与层级 |
| 3 | 角色身份锚（正面参考） | 锁脸、发型、比例 |
| 4 | 体型 / 对照锚 | 锁多角色间的体型差 |
| 5 | 源事件框架 | 只锁顺序与动作，不锁外观 |

写完回查一遍：填充层里是否还残留源提示词的默认风格词（常见是赛博霓虹、深紫背景）。

**主体本色不属于填充层**：产品 / 角色的本色、材质色、可见表面处理**不随风格替换**——Apple 风不是把产品变白变银，纸艺风不是把纸变牛皮黄。能向选定风格偏移的只有背景、光线环境、构图。

## 二、参考图窄职责

每张参考图只给它**一件事**，交叉会互相污染：

| 参考角色 | 只锁 | 明确不许贡献 |
|---|---|---|
| 排版参考卡 | 字体质感、版式比例、文字动效语言 | 人物、场景 |
| 角色参考卡 | 身份、五官比例、发型、服装轮廓、体态 | 场景、排版 |
| 场景参考卡 | 场景风格、空间氛围、画质纹理、景深 | 人物身份 |
| UI / 确认图 | 布局、层级、色系统、按钮结构、字号阶梯 | 具体角色外观 |
| 体型对照 | 两角色可见体型对比（防趋同） | 单独身份 |

多角色片至少给「身份锚 + 体型锚」两张，否则两人体型会趋同。

**锚图出独立单张，不做四格拼版 / 分屏 / 参考板**：视频模型会把拼版布局当成成片版式照抄。要控三个面（主体 / 细节 / 收尾文案）就出三张独立图；锚图只是参考，不当分镜替身用。

## 三、分镜表：列与密度

**常用六列**：

```
时间 | 连续性交接 | 参考锚（空间 + 身份）| 钩子类型 | 逐秒描述 | 声音与台词轨
```

- `逐秒描述` 必须是逐秒可执行的指令，不是一句情节概括；
- `连续性交接` 写清本镜从上一镜的哪一帧 / 哪个动作接上；
- 表是给模型执行的施工表，不是美术稿 —— 单元格里不留长段落。

镜数 / beat 密度（官方给的默认值，按用途二选一）：

| 时长 | 镜头数（讲解 / 定格类） | beat 数（产品 / 品牌类） |
|---|---|---|
| 5s | 2–3 | 3–4 |
| 10s | 3–4 | 5–7 |
| 15s | 4 | 5–9 |
| 30s | 5–6 | 8–12 |
| 60s | 7–9 | — |

一镜一件事：一个主行动，次层延后 0.2–0.5s 进入。

### 3.1 多镜片每镜必写的三样

缺一样就会「一镜一个片」：

- **空间锚卡四子字段**：固定地标 + 其画面相对位置（`门框：右三分之一`）／每个在场角色的位置、朝向、初始姿态（机位视角）／**已退场角色的状态**（上一镜在、这镜不在的人写明去哪了——不写模型会补一个第三人）／光基线（主辅轮廓光方向，可加本镜修正）。
- **双向交接**：`从 S(N-1) 接`（一两句复述上一镜结尾状态）+ `交给 S(N+1)`（一句铺垫下一镜开场）。
- **钩子类型**（受控词表）：`setup / visual-joke / reversal / reveal / callback / suspense / tender / chase / expression-beat / climax`——用来查分布，别整片都是 reveal。

### 3.2 逐秒面板四象限

逐秒描述再拆一层，一秒一块，块内四象限：`时间码` ／ `姿态+表情`（轮廓、关键道具握法、视线、表情路径；弹性动作写明 squash / stretch / anticipation / overshoot）／ `机位运镜`（景别、推拉摇移、手持抖、锁定、环绕，必要时荷兰角）／ `声音+锚点`（旁白 / 台词 / SFX / 静音 + 空间锚）。

面板数 = 秒数（3s 三块、6s 六块；7s+ 每秒一块，亚秒关键 beat 才加小块），必须从首帧铺到末帧不留空档。旁白秒标 `旁白闭口`、出镜台词标 `开口：说话人`——口型不同步就靠这条兜。

## 四、>15s 必须拆镜（H3 单条上限 15s）

拆镜不是切片。五条连续性锁，缺一条就会「一镜一个片」：

1. **音频基线唯一**：整片锁一条 Master Audio（含全部人声与节拍），各分镜只对齐它，不用各片自带音轨。
2. **剪点落在自然断点与拍网格**：气口、停顿、snare / drop；尽量压 1/4 或 1/8 拍；不在活跃元音中间硬切（除非下一镜是连续口型的特写）；点头、手势、眨眼可用变速对齐拍点。
3. **视觉头尾接续**：同场景 → 上镜尾帧作下镜首帧；硬切 → 同向运镜或遮挡匹配切。
4. **影调统一**：每镜带同一段「美学头」（grain / LUT / 光向），成片再统一一次。
5. **文字动量传递**：上镜文字在重拍上碎开或扫出，下镜文字在重音上砸入。

## 五、画面文字：两条互斥策略

先判断这条片子要不要画面文字，然后二选一，不要中间态。

**A. 不要文字**（讲解 / 氛围 / 写实类）：

负向段显式写 `no readable letters, no numerals, no UI, no subtitles, no watermark, no logo`。
不写这一句，模型会自己加字、加浮标、加水印。

**B. 要文字**（广告 / 游戏 UI / MV 排版）：

- 一镜一行，3–5 个英文词，≤ 32 字符（含空格）；不要孤立的 1–2 词标签。
- 禁止：两行、标题 + 副标题、多个文字块同时出现、字幕位（画面下方）。
- 字色 ≤ 2 种：黑/白 + 产品主色；白底禁白字。
- **文案里不许用箭头 / 斜杠 / 加号分隔** —— 模型会把符号画进画面。拆前后半句只用自然语言写「前半 …／后半 …」。
- 有唱词时：可见文字必须与所唱**逐字一致**。
- **两段式文案在同一条行内完成**：前半先淡入 / 滑入，后半稍后进入，前半在同行内轻移让位（约 10–15px 或字宽 8–12%）。不要为了躲开两行就把文字做成完全静止。
- **不必每镜都有字**：10 秒片通常「中段一次 + 结尾一次」；模型老写错字就主动降频。收尾镜必须有一行稳定的单行文案。
- 文字锚图只管字体、位置、单行与两段配色，不代表全片只能用它那一行。
- 文字是空间层不是字幕条：可落在前/中/背景，但不压眼睛与主要表情，关键口型时避开嘴部。
- 收尾镜：单帧完整主体 + 单行文案；禁止田字格、分屏、九宫格、参考板版式收尾。

## 六、音频默认策略

默认口径：**保留实体音效（SFX），不默认加 BGM / 口播 / 字幕。**

- 要 SFX 就点名具体音：纸片滑动、弹出、压平、轻擦、机械扣合、UI 悬停声。
- 用户没要就不加，不要默认「短视频必须有 BGM」。
- 合成时保留分镜原音轨，除非用户要静音 / 换配乐 / 单独混音。
- 不要 BGM 时写 `non_diegetic_music: N/A`。
- **别替用户推断**「讲解片必须口播」「社交片必须有 BGM / 字幕」：没选就只留 SFX。
- 要 BGM 时按**题材与文化**选，不按风格套路：节日 / 文化题材用该文化自己的器乐语言（中秋 → 古筝、琵琶、箫、轻打击），科普课堂 → 马林巴、木琴、拨弦、暖调；人声下 ducking；忌厚重电影低音与激进 EDM。
- SFX 按运动节拍点设计、克制使用（翻页 / 剪刀 / 纸板滑 / 轻响 / 胶带撕），不要堆成卡通音效。

## 七、单镜头段落顺序（三个官方范式）

**A. 生活场景融合（15s 单镜，11 段）**

```
1 开头句（时长 + 画幅 + 融合方式）
2 实拍空间与拍摄质感
3–7 时间分区（0-3 / 3-6 / 6-10 / 10-13 / 13-15 秒，每区一个新事件）
8 材质 / 笔触质感
9 相机追随方式
10 禁止事项
11 环境音
```

- 相机要**慢半拍**：主体已出画才摇 / 推过去，不要居中追焦。
- 连续变形时每个新形态保留前一形态的痕迹（线条、尾、色痕、轮廓），且不得凭空出现第二个角色。
- 全片在同一空间或相邻范围连续展开，不剪辑跳场。

**B. UI / 游戏开场（每段 6 小节）**

```
[起-止秒] — 段落名
景别/机位 → 画面内容 → UI 结构（逐字写屏上文本）→ 动作 → 动态风格填充 → 声音
```

- 屏上每个按钮、名称、状态、菜单项都写原文，含大小写。
- 身份锁要写死四条：禁止身份交换、脸互相融合、昵称互换、体型趋同。
- 若生成不带音频，声音行标 `若生成无音频则忽略声音执行`，不要删。

**C. MV / 歌词排版（逐镜脚本）**

```
[全局美学与角色锁]：（一段全局锚定）

Shot N（0.0–3.5s）
Vocal Line: "..."
Typography: "..."
Visual & Action: ...
Camera & Motion: ...
Transition Out: bass hit 上硬切到 Shot N+1 / 同向甩镜
```

- 每镜只给一个主排版事件；排版是空间里的图形主体（可被肩、手、前景遮挡），不是字幕条。
- 转场只硬切（气口 / 重拍 / 遮挡匹配），不要淡入淡出。

## 八、节奏与运动语言（跨垂类通用）

峰值 = 动作完成 / 主体入场 / 后半文案落地 / 全貌收尾；刹车 = 细节停顿 / 文案可读停留 / 末帧保持：

| 片长 | 峰值 | 刹车 |
|---|---|---|
| 5s | 1 小峰 | 1 稳定收尾 |
| 10s | 1–2 | 1–2 |
| 15s | 2–3 | 2 |
| 30s | 3–4 | 3 |

- **过渡由真实元素驱动**：主体边缘、材质高光、开合 / 旋拧 / 滑入、色块进出、同向运镜、同形剪影、遮挡匹配。禁用无意义白闪、氛围粒子、随机光效、随机切。
- **开场不留空**：前 0.5s 就给主体动作或强角度，不要空镜等音乐。
- **不要全片同一个缓动**：至少三档节奏（快切段 / 中速段 / 静止段）；全程一种 easing 会显得廉价。
- **景深四层**：前景遮挡物 / 中景主体（信息都放这层）/ 背景视差 / 远景环境。背景也要有小运动（云、叶、灯、视差位移）——背景全静会立刻显得假。
- **转场守材质物理**：翻页、展开、拉片、划像、圆形遮罩、门开、剖面分层、碎屑、胶带揭，按素材来定；禁电子扫描线、霓虹故障、玻璃碎裂、金属划像、科幻粒子。
- **主体可读性优先**：轮廓清楚、单行文案可读、主 SKU 不被挡；用户没给 logo 就不要生成假 logo，也不要用假 HUD / 装饰玻璃卡 / 文字墙 / 未验证数据撑场面。

### 常见返工的处理顺序

| 症状 | 先改什么（按序） |
|---|---|
| 文字没出现在视频里 | 重跑提示词并要求「中段 + 末镜都要有字」；仍不行再退回文字锚图 |
| 文字变形 / 糊 | 先减少屏上字数；再重出文字锚图；最后把该镜降级为基于锚图的轻微运动 |
| 身份互换 / 脸融合 | 强化三处：名字、位置、配色（三者一起改，只改其一无效） |
| 角色漂移 | 复用上传参考 + 显式写身份锚（脸型、发型、服装、比例），别只说「保持角色一致」 |
| 风格弱 / 混着源风格 | 重写风格段（整体风格 / 配色 / 角色风格 / 背景 / UI / 按钮 / 图标 / 字体），**不要改布局框架** |
| 场景对不上（地标错位） | 回查空间锚卡的「固定地标」是否写了画面相对位置；没写就是没锁 |

## 九、负向清单模板

英文一串列举最省 token、边界最硬：

```
No third character, no duplicated character, no character swapping, no merged faces,
no identical body proportions, no changing faces, no changing hairstyles, no hard cuts,
no random camera shake, no floating limbs, no unreadable UI, no random letters,
no misspelled text, no extra menu items, no watermark, no white flashes, no decorative particles,
no fantasy light streaks, no electronic scanline transitions, no smooth CG morphing, no plastic surfaces.
```

按需裁剪，但**至少覆盖三类**：身份类、物理类（穿模 / 漂浮 / 断肢）、画质类（糊字 / 水印 / 闪烁）。

## 十、八类垂类速查

| 垂类 | 典型时长 / 画幅 | 核心结构 | 必写字段 | 硬禁止 |
|---|---|---|---|---|
| 极简产品广告 | 5–15s · 16:9 / 9:16 | beat 表（主色变体 + 文案前后半） | 产品主色、可展示结构、英文文案、字色 | 双行字、字幕位、田字格收尾、未授权 logo |
| 3D 动画短片 | 5–10s / 镜，多镜 | 角色卡 → 场景卡 → 六列分镜 → 单镜 | 角色三视图、连续性交接、逐秒指令 | 角色漂移、跨镜换装、体型趋同 |
| 纸艺定格讲解 | 5s / 镜，16:9 | 分层景框 + 纸偶微动 | 纸纹、分层、物理阴影、慢推 / 视差 | 平滑 CG 变形、融化、塑料感、高速运镜 |
| 拼贴讲解 | 5–10s / 镜，16:9 | halftone 拼贴 + 停格组装 | 拼贴材质、点名 SFX、无字 | 可读文字、平滑数字运镜、默认加 BGM |
| 品牌宣传 | 15 / 30s | hook → 意图 → 机制 → 能力 → 证明 → 收尾 | 品牌事实、素材出处、beat 表、CTA | 未授权商标、编造参数、假 HUD |
| MV / 歌词排版 | >15s 拆镜 | Master Audio + 逐镜歌词 / 排版 / 转场 | 锁定歌词、Typography 字段、剪点 | 淡入淡出（只硬切）、文字压眼、字幕条 |
| 双人游戏开场 | 10–15s | 确认图 → 视频（同一事件框架） | UI 逐字文本、双人身份锚、体型差 | 第三人、身份互换、分屏 |
| 手绘发光 × 实拍 | 15s · 16:9 | 11 段范式（见 §七 A） | 0–3s 接触、连续变形、相机延迟 | 3DCG、毛绒感、恐怖元素、矢量平滑线 |

## 十一、遇到垂类整包需求：建议用户安装官方 skill

本文件只覆盖提示词层。官方那 8 个垂类是**可直接安装的 skill 包**（`SKILL.md` + `SKILL.cn.md` +
`meta.yaml`，两类带 `references/` 模板），装上以后自带该垂类的模板库、默认值、禁区与自检清单。
**命中下面任一条就别硬用本文件拼，直接建议用户装对应那个包**：

| 判据（命中即推荐） | 本 skill 为什么顶不上 |
|---|---|
| 用户要的是**整条片子落地**，不只是提示词（素材准备 → 分镜表 → 逐镜生成 → 拼接 → 配乐 → 审核） | 流程编排、交付物形态、审核门不在本 skill 范围 |
| 用户要照抄官方模板全文（六小节分镜表、确认图模板、QC 清单、模型选型与 fallback 策略） | 本文件只提炼了段序与判据，模板逐条措辞在包里 |
| 用户在同一垂类反复返工（产品广告 / 3D 动画 / 纸艺 / 拼贴 / 品牌 / MV / 游戏开场 / 手绘实拍） | 那个包有该垂类的成套默认值与自检清单 |

**推荐时必须说清它能干什么、不能干什么**——官方 frontmatter 自己写着
`compatibility: Requires the MiniMax Hub agent ... not portable to generic agent harnesses`：

- **能直接用**：模板、分镜表规范、QC 清单、模型选型与降级策略、提示词范式（纯文档层）。
- **不能直接用**：画布工作区、Hub 的生成 / 路由工具、审核卡片那套流程编排（换到本机就跑不通）。
  所以定位是「装成一个垂类模板库」，不是「装了就能一键出片」。

> 这块官方有现成的 `xxx` skill，带完整分镜模板和自检清单，装上当模板库比我在提示词层拼省事——要装吗？

**安装（装成独立本地 skill，放 `~/.workbuddy/skills/<目录名>`）**：

```bash
BASE="https://raw.githubusercontent.com/MiniMax-AI/MiniMax-H3/a107547/skills"
NAME=minimalist-product-ad-generator          # 换成要装的那个目录名
D="$HOME/.workbuddy/skills/$NAME"
mkdir -p "$D" && for f in SKILL.md SKILL.cn.md meta.yaml; do
  curl -sf --noproxy '*' --retry 3 "$BASE/$NAME/$f" -o "$D/$f" || echo "拉取失败：$f"
done; ls -l "$D"        # 应有 3 个文件
```

- `meta.yaml` 带 trigger-words，**要一起拉**，缺了触发词识别不到。
- 偶发断连（本机实测第一次拉会静默漏一个文件）：`curl -f` 会打 `拉取失败：xxx`，补跑那一条；
  最后按文件数自检——三件套 = 3、3D 动画 = 8（3+5）、双人游戏开场 = 5（3+2）。
- 装完让用户重启会话（或重新加载 skill）才在列表里出现；列表里已经有了就不要重复装。
- `--noproxy '*'` 是本机约定（有系统代理时请求会被转给代理）；raw 不通时用 api 兜底
  （`GET /repos/MiniMax-AI/MiniMax-H3/contents/skills/<目录>/<文件>?ref=a107547` 取 base64 解码落盘）。
- **别把这 8 个包塞进 h3-playbook 的 `references/`**：它们是独立 skill，塞进来会与本文件的判据重复且互相打架。
- 装完最值得先翻的两处模板：`co-op-game-intro-generator/references/h3-video-prompt-template.md`（UI 类六小节完整措辞）、
